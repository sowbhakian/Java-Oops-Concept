DBMS:

What is a transaction?
	A unit of work performed within a DB that must be atomic, consistent, isolated, and durable (ACID properties).

What are ACID properties?
	Atomicity 	- All or Nothing
	Consistency - Maintains valid data and rules	Integrity, constraints
	Isolation 	- Concurrent transactions shouldn’t interfere
	Durability	- Once committed, always saved

Difference between UNION and UNION ALL?
	UNION: Removes duplicates.
	UNION ALL: Includes duplicates, faster than UNION.

	- Thread Execution is dependent on the Thread Priority ?? NO
	
		Thread priority in Java is only a scheduling "hint". A higher-priority thread is not guaranteed to block or starve lower-priority threads, even in an infinite loop or when competing for the same lock. Actual behavior is JVM and OS dependent, and Java provides no guarantees of fairness or starvation prevention. Proper concurrency control must be implemented using synchronization primitives rather than relying on priority.”

	
	- Monitor Ownership (Core Definition)

		Lock monitor ownership means that a thread has successfully acquired an object’s monitor and therefore has the legal right to execute code synchronized on that object.

		Only the owner thread can:
		Execute the synchronized code Call wait(), notify(), notifyAll() on that object
		If a thread tries to do these without owning the monitor, Java throws: "IllegalMonitorStateException"
		
		Monitor Ownership Is Acquired Using "synchronized"
		
		Monitor Ownership Rules: 
		Only one thread can own a monitor at a time, Other threads attempting to enter:
		Go into BLOCKED state

		Ownership is released when:
		The synchronized block/method exits Or wait() is called (special case)
	
			“Lock monitor ownership means a thread has exclusive control over a synchronized object. Thread priority does not influence lock acquisition, and a higher-priority thread can be blocked indefinitely by a lower-priority thread holding the lock. Java provides fairness only through explicit constructs like ReentrantLock(true), not through intrinsic locks or priority.”
			
	- Locks, Priority, Scheduler:
			Scheduler decides who gets CPU
			Locks decide who gets access to shared state
			Priority influences scheduling only
			Locks override priority
		
	- This Is Called Priority Inversion
		Low-priority thread indirectly blocks a high-priority thread.
		Low (A) → owns lock
		Medium (B) → runs freely
		High (C) → waits forever
		
			Thread priority decides who gets CPU.
			Locks decide who gets data.
			CPU does NOT override locks.

	- Use ConcurrentHashMap when:

Thread Lifecycle:
------------------

	State				Description
	-----				------------
	New					Thread is created but not started.
	Runnable			Thread is ready to run and waiting for CPU time.

	Timed Waiting		Waiting for a specified time (e.g., sleep, join).
	Terminated			Thread has finished execution or was stopped.

Common Issues
	- Race Condition: Two threads access shared data simultaneously.
	- Deadlock: Threads wait on each other indefinitely.
	- Starvation: A thread never gets CPU time.
	- Livelock: Threads keep changing state but make no progress.
	
	
1. What is multithreading in Java?
	Multithreading is a programming technique where multiple threads run concurrently to perform tasks. It helps improve performance by utilizing CPU cores efficiently.

2. Difference between process and thread
	- Process: Independent execution unit with its own memory space.
	- Thread: Lightweight sub-process sharing memory with other threads in the same process.

3. How to create a thread in Java?
	- Extend the Thread class and override run()
	- Implement the Runnable interface and pass it to a Thread object
		Thread thread = new Thread(new MyRunnable()); --> we need to pass the class that implements the runnable

4. Thread vs Runnable ##Important!!
	- Thread: Inherits thread behavior directly.
		-  Multiple Inheritance Limitatio --> class MyTask extends Thread, AnotherClass { // ❌ Not allowed
		- Thread creates a full thread object, which is heavier.
		
	- Runnable: Promotes better design by separating task from thread mechanics.
		- Runnable is preferred when using ExecutorService, ThreadPoolExecutor, or ForkJoinPool
		- Runnable is lighter because it doesn’t carry thread overhead.

7. start() vs run() ##Important!!
	- start(): Creates a new thread and calls run().
		Creates a new thread and runs the process in the new thread. (Multithreading)
	- run(): Executes in the current thread, not concurrently.
		Runs in the same main thread, does not create the new thread  (not Multithreading)
	
8. User vs Daemon threads ##Important!!
	- User thread: Keeps JVM alive.
	- Daemon thread: Background thread that dies when all user threads finish
		Thread daemonThread = new Thread()
		daemonThread.setDaemon(true);
		
		If it is not set as true, then the daemonThread will run infinitly!!

10. What is synchronization?
	It’s a mechanism to control access to shared resources to prevent race conditions.

11. Synchronized block vs method ##
	- Method: Locks the entire method.
	- Block: Locks only the critical section.

12. Deadlock
	Occurs when two threads wait on each other’s locks. Prevent using lock ordering or timeout strategies.
	
	- Lock Ordering
	- Try-Lock with Timeout - Use ReentrantLock with tryLock(timeout) to avoid
	- Deadlock Detection (Advanced) Some systems implement deadlock detection algorithms that monitor thread states 
	- Avoid Nested Locks
	- Use Higher-Level Concurrency Utilities (- ExecutorService (thread pools), ConcurrentHashMap, BlockingQueue)
	
13. Race condition ##
	Multiple threads accessing shared data without synchronization. Use synchronized, Lock, or atomic variables.
	- Use synchronized Blocks or Methods
	- Use Atomic Variables, AtomicInteger, AtomicLong, etc., guarantee thread-safe operations without explicit locking.
		AtomicInteger count = new AtomicInteger(0);
		i = i + 1;
		look simple but are not atomic → they break into multiple steps: 
		Read value, Increment value, Store value
		If two threads do this at the same time, values can be lost → race condition.

	ASDASDASDASDASDASDASDASDQASDASD
	
14. Thread starvation ##
	A thread waits indefinitely due to other threads monopolizing resources. Use fair locks or priority management.

15. Thread safety
	Ensuring shared data is accessed in a synchronized way. Use synchronized, Atomic classes, or thread-safe collections.
	
7. wait(), notify(), notifyAll()
	- wait(): Pauses thread until notified.
	- notify(): Wakes one waiting thread.
	- notifyAll(): Wakes all waiting threads.
	
18. Monitor
	Each object in Java has an intrinsic lock (monitor). Used in synchronization.

19. Reentrant synchronization
	A thread can re-acquire the same lock it already holds. Java’s synchronized and ReentrantLock support this.

20. Executor framework
	Manages thread pools and task execution. Use Executors.newFixedThreadPool() etc.

21. Executor vs ExecutorService vs Executors
	- Executor: Basic interface.
	- ExecutorService: Adds lifecycle management.
	- Executors: Factory class for creating executor instances.

22. Callable vs Runnable
	- Runnable: No return value.
	- Callable: Returns a result and can throw exceptions.

	Why Java 21 Introduced SequencedCollection and SequencedMap
	-----------------------------------------------------------

		Before Java 21:
			- LinkedHashMap, LinkedHashSet, and ArrayList preserved order.
			- But they didn’t share a common interface to express that ordering.

		Now:
			- SequencedCollection, SequencedSet, and SequencedMap provide a standard contract for ordered access.
			- This makes APIs more predictable, interoperable, and generic.

		These interfaces add new methods that weren’t available in older classes:
			- getFirst(), getLast()
			- removeFirst(), removeLast()
			- reversed()
