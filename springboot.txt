Why Spring Boot ?
===============
	Before Spring Boot:
		• Dependency Management (pom.xml)
		• Define Web App Configuration (web.xml)
		• Manage Spring Beans (context.xml)
		• Implement Non Functional Requirements (NFRs)
			Login, Error Handling, Monitoring
			
	Build QUICKLY
		• Spring Initializr
		• Spring Boot Starter Projects
			- Web Application & REST API - Spring Boot Starter Web (spring-webmvc spring-web, spring-boot-starter-tomcat, spring-boot-starter-json)
			- Unit Tests - Spring Boot Starter Test
			- Talk to database using JPA - Spring Boot Starter Data JPA
			- Talk to database using JDBC - Spring Boot Starter JDBC
			- Secure your web application or REST API - Spring Boot Starter Security
		• Spring Boot Auto Configuration
			Example: Spring Boot Starter Web
			- Dispatcher Servlet (DispatcherServletAutoConfiguration
			- Embedded Servlet Container Tomcat is the (EmbeddedWebServerFactoryCustomizerAutoConfiguration
			- Default Error Pages (ErrorMvcAutoConfiguration)
			- Bean<->JSON (JacksonHttpMessageConverters Configuration)
		• Spring Boot DevTools - If this is added in the pom.xml no need do the restart manually each and every time, If any changes in the pom.xml manual restart is required.
			<groupId>org.springframework.boot</groupId>
			<artifactId>spring-boot-devtools</artifactId>

	Be PRODUCTION-READY
		• Logging
		• Different Configuration for Different Environments
		• Profiles, ConfigurationProperties
		• Monitoring (Spring Boot Actuator)
	
	Embedded Server: 
		• In the old way we need to install the app server (Tomcat or Websphere), Install java and need to deploy the WAR file in the appserver. 
		• Now the Springboot by default has the embedded server, we can run this Jar directly no need of appserver
		• Run as maven "clean install" this will generate a runnable jar to execute it.
		• "ToBeOnjpmc-0.0.1-SNAPSHOT.jar" is created under the targe folder in the maven project.

Key Features:
-------------
	- Dependency Injection (DI): Helps manage object creation and their dependencies automatically.

	- Aspect-Oriented Programming (AOP): Separates cross-cutting concerns like logging, security, etc.
		* Spring uses proxies (via Spring AOP) to intercept method calls and apply additional behavior.

	- Modular: You can use just what you need (e.g., Spring MVC for web, Spring JDBC for DB).

	- Integration Support: Easily integrates with Hibernate, JPA, JMS, Kafka, etc.


application.properties
======================
	SPRING:
	spring.application.name=demo
	server.port=8080             
	server.servlet.context-path=/myapp  							[you change it, all your endpoints will be prefixed with it]
	
	DATABASE:
	#spring.datasource.url=jdbc:mysql://localhost:3306/mydb
	#spring.datasource.username=root
	#spring.datasource.password=password
	#spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver

	#spring.jpa.hibernate.ddl-auto=update     							# create | update | validate | none
		none: Hibernate will do nothing with the database schema.You have to manage schema manually (via SQL scripts, Flyway, Liquibase, etc.).
		validate: Hibernate compares the entities (Java classes) with the existing database schema. If something is missing/mismatched, it throws an error. No schema changes are made automatically.
		update: Hibernate will create new tables/columns if they don’t exist and update schema when entity changes are detected.
		create: Hibernate drops existing schema and creates new tables from scratch every time the app starts.
		create-drop: Same as create, but additionally drops schema when the app shuts down.
		
	#spring.jpa.show-sql=true											[Hibernate will print SQL queries in logs.]
	
	#spring.jpa.database-platform=org.hibernate.dialect.MySQL5Dialect	[It will generate SQL that’s compatible with DB]

	LOGS:
	#logging.level.root=INFO
	#logging.level.org.springframework.web=DEBUG
	#logging.file.name=logs/app.log

	PROFILES: File name should be "application-sowbhi.properties"
	#spring.profiles.active=sowbhi
	
Annotation:
===========
	@SpringBootApplication:
	-----------------------
		@Configuration	
			Allows defining beans with @Bean (In Spring we used to config in the applicationContext.xml, no need to config xml here)
			
		@EnableAutoConfiguration	
			Automatically configures Spring components (like DataSource, MVC, Security, etc.) based on classpath(dependencies i.e classfiles) and application.properties

		@ComponentScan(basePackages = {"com.myapp", "com.external"}) - Automatically finds all the  class and registers beans/components in the current package and sub-packages and make it ready to if @Autowired is used directly it can be used.
				@Component	- This make the spring to register the beans
				@Service
				@Repository		= 
				
				@Controller - This class will handle web requests (HTTP GET, POST, etc.) and return a View (HTML page) or raw string based on the annotations.
				
				@ResponseBody - The return value of this method should NOT be resolved as a view name, but instead written directly into the HTTP response body.
					
				@RestController	= @Controller + @ResponseBody - If this is not given then the returned string is considered as the view name, Spring will look into template folder to render the html
					
				@RequestMapping - general purpose annotation that can handle all HTTP methods by default it is get
					Eg: @GetMapping → @RequestMapping(value='/home', method = RequestMethod.GET)
		
		@ConfigurationProperties(prefix="login") - Helps to load the values from the "application.properties"
			- The Spring auto binds the property with the model class and exposes only the model class.
		
		@Before("execution(* com.example.service.*.*(..))")
		
Spring IoC container:
=====================
	Inversion of Control - control of object creation and dependency management is handed over to the framework.
	
	Manages the life cycle of Spring beans (objects).

	Resolves dependencies between objects.

	Configures beans based on annotations or XML configuration.
	
	Eg:
	---
		BeanFactory - org.springframework.beans.factory.BeanFactory	
		Lightweight, lazy initialization

		ApplicationContext - org.springframework.context.ApplicationContext	
		More advanced (used in most real projects), supports AOP, event propagation, etc


lazy-init="true":
=================
Default Behavior: Spring eagerly creates all singleton beans when the application context is initialized.
Lazy Initialization: With lazy-init="true", the bean is created only when first requested—either via injection or a direct call to getBean().
